# Offline loot presentation proof

Every preview sheet is marked **OFFLINE EXACT-TRANSFORM COMPOSITE, NOT GAMEPLAY SCREENSHOT**.
These are source-pixel composites for the approved browser-blocked review route. No browser,
Mac, tunnel, image generation, new artwork, or production code change is involved.

## Reproduce

From the repository root, with the repository's normal Node dependencies installed and
Python 3 + Pillow available:

```sh
npx vitest run --config diagnostics/loot-visuals/vitest.config.ts
python diagnostics/loot-visuals/compose.py
```

The compositor uses DejaVu Sans from `/usr/share/fonts/truetype/dejavu/` only for sheet
headings and captions. In-game labels use the actual project's pixel-font drawing commands.
The diagnostic config is opt-in and is not included in ordinary unit-test discovery.

Generated files:

- `recording.json`: complete machine-readable calls, source hashes, source-generated texture
  rectangles, transforms, labels, lights/shadows, simulation success messages and receipt expiry.
- `preview/01-floor-terrazzo.png`: cash, snack, common and rare before/after on light floor,
  with native 1x and nearest-neighbor 2x crops.
- `preview/02-floor-carpet.png`: identical cases on dark source-generated carpet.
- `preview/03-settled-motion.png`: six source-recorded settled ticks, before and after,
  with actual scale and Y-position captions; enlarged 3x nearest-neighbor.
- `preview/04-nearby-labels.png`: actual name, rarity, value, health-full, healing and
  step-away labels at native 1x and enlarged 2x.
- `preview/05-collection-receipts.png`: real simulation collection outputs and expired state.
- `preview/fx-*.png`, `preview/floor-*.png`: lossless inputs replayed from source commands.

Bulk generated JSON and PNGs are evidence outputs, not required runtime or patch inputs.
Keep this README, both scripts, the diagnostic config and the frozen baseline body to regenerate.

## What is exact

The before body is frozen in `baseline-drawTokens.js.txt` from commit
`c873f4bdbc0c190c471b17e270934eb7b9795092` (the isolated portable snapshot of verified
main `11b0c68c134615295b308563cda1f31a51b32b6a`), method `MvpRunView.drawTokens`.
Only the TypeScript generic in `new Set<string>()` was erased for direct JavaScript execution.
The diagnostic does **not** extract before behavior from the current HEAD, so it continues
working after the loot change is committed or applied elsewhere.

The recorder imports the actual current `LootView`, `lootCues`, procedural-texture helpers,
pixel font, simulation collection functions and item-path resolver. Fake Phaser image and
graphics surfaces record the real renderer's positions, origins, scales, alpha, texture keys,
depth and rectangle/triangle commands. No corresponding renderer math or label wording is
reimplemented in Python. Provenance hashes identify the current source and native item PNGs.

The coin and pretzel are generated by the actual `ensureFxTextures` calls. Native 32x32
Pump-Action Soaker and Golden Mop PNGs are loaded unchanged. Both floors are generated by the
actual deterministic source routine. Nearby text uses actual `ensurePixelLabel` paint calls,
including its one-pixel outline. The compositor applies the recorded affine coefficients to
the unchanged pixels, then enlarges the completed native crop with nearest-neighbor sampling.

The stills use world position (480,260), tick 43, and droppedTick 0. This deliberately shows
the old cash token's edge-on clamp: 0.32 horizontal scale versus the new 2.0 fixed scale.
The motion sheet samples ticks 24,32,39,47,55,63. The old rare scale ranges approximately
1.15–1.35; the new rare stays at 1.0 with an external shape badge. Label cases place the
player 50px from the pickup in a safe room. Receipts are produced by calling the actual
`collectTokens` / `collectItemDrops` functions at tick 61, then recorded after expiry at 140.
The diagnostic asserts visible receipts followed by their absence and validates representative
nearby label wording. It does not synthesize success lines for the receipt pictures.

## What this does not verify

This is **not** a rendered Phaser frame and is not pixel-identical browser/WebGL evidence.
Pillow rasterizes recorded triangle edges and nearest-neighbor affine transforms; GPU
half-pixel/edge coverage and alpha rounding may differ. Rectangle and font source commands
are retained, but their software compositing is not the browser's canvas implementation.

Room tint/lighting, bloom, contact shadows, actors, occluders and camera/UI composition are
omitted equally on both sides. All requested light and shadow calls remain in `recording.json`
for audit; no attempt is made to approximate the full scene's light pass. Therefore the
light/dark sheets compare source floor palettes and cue readability, not the final illuminated
room. No conclusions about real-time performance, movement feel, full-room occlusion, active
combat overlap or a playable browser flow should be inferred from these sheets.

All five sheets were opened and visually inspected after generation. They show the narrower
old cash token, steady new scales, separated rare diamond, health-full wording, identity text,
and real short-lived collection receipts. Live gameplay visual QA remains outstanding.
