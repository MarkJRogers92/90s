# DEAD MALL M0-M1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a locally running and tested Janitor combat-room prototype with movement, directional mop combat, two enemies, health, pause, terminal states, and reliable restart.

**Architecture:** Plain TypeScript state and fixed-tick functions own every gameplay decision. Phaser adapts real browser input to that simulation and renders snapshots of the same state; Vitest proves rules and Playwright proves the user path.

**Tech Stack:** Node 24.20.0, npm 11.19.0, TypeScript 7.0.2, Phaser 4.2.1, Vite 8.3.0, Vitest 5.0.0, Playwright Test 1.63.0.

**Spec:** `docs/superpowers/specs/2026-09-13-dead-mall-m0-m1-design.md`

## Global Constraints

- Stop at M1; do not add item composition, shopping, theft, Heat, fusion, procedural generation, or saves.
- Keep one renderer-independent authoritative simulation advancing at a fixed 60 Hz.
- Pause on blur and clear held input before explicit resume.
- Use local original graybox visuals and no runtime network requests.
- Add no backend, accounts, analytics, telemetry, cloud service, deployment, or external-model runtime.
- Keep the development debug bridge behind `VITE_ENABLE_DEBUG_BRIDGE=true` and absent from a normal production runtime.
- Follow test-first red-green-refactor for production behavior; record actual commands and results.
- Do not push or publish.
